## 구현 메모
- 변경한 파일: `apps/web/src/store/useWorkspaceNavigationStore.ts` 추가, `store/.gitkeep` 제거, `App.tsx`, `WorkspaceLayout.tsx`, `scripts/verify-sidebar.mjs`, `apps/web/package.json`, `package-lock.json`, `README.md`, 이 문서 수정.
- 의사결정 및 이유: 뷰와 선택한 채널·DM을 단일 Zustand 스토어에 두었다. 사이드바와 본문은 필요한 값만 선택해 구독한다. 채널·DM 선택 액션은 선택 값과 채팅 뷰를 한 번에 갱신한다. 별도 저장소에 영속화하지 않아 새로고침하면 샘플 초기 상태로 돌아간다.
- 예외 상황·권한·로딩 검토: 현재 목록은 샘플 데이터이고 외부 요청이 없어 인증 권한, 로딩, 서버 실패 상태가 없다. 알 수 없는 대화 식별자는 기존 이름 조회 함수가 `대화`로 표시한다. 실제 로그인·워크스페이스 변경 시 선택 상태 초기화와 권한에 따른 채널 목록 갱신이 필요하다.
- 발견한 문제/해결: 4일차에는 선택 상태가 `App` 내부에 있어 다른 구성 요소가 직접 공유할 수 없었다. 스토어로 옮기고 컴포넌트를 다시 마운트한 뒤에도 선택이 유지되는지 검사했다.
- 다음 일차에 넘길 사항: 6일차 Firebase 환경 구성 후 실제 로그인 흐름을 연결할 때 워크스페이스 전환과 로그아웃에 맞춘 상태 초기화를 추가한다. 데스크톱·모바일 화면 육안 확인은 아직 남아 있다.

## 포트폴리오 기록
- 문제 정의: 사이드바와 본문의 선택 상태가 한 컴포넌트의 로컬 상태에 묶여 있어 이후 기능이 같은 상태를 쓰기 어려웠다.
- 선택한 접근과 대안: Zustand 스토어에 뷰·대화 선택과 액션을 함께 두고 두 구성 요소가 필요한 상태만 구독하게 했다. 현재 단계에서 영속화는 적용하지 않았다.
- 검증 근거(수치 임의 생성 금지): `npm run typecheck`, `npm run lint`, `npm run build:web`, `npm run test:ui` 통과. UI 검사에서 보드·캘린더 전환, DM·채널 선택, 선택 상태의 스토어 반영과 컴포넌트 재마운트 후 유지를 확인했다. 브라우저 육안 검증은 미완료.
