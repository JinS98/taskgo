## 구현 메모
- 변경한 파일: `apps/web/src/features/tasks/TaskCreateDialog.tsx`, `TaskCreateDialog.module.scss`, `createTaskApi.ts`, 채팅·워크스페이스 연결 파일, `apps/web/scripts/verify-live-chat.mjs`, README와 데이터 모델 문서.
- 의사결정 및 이유: 저장이 확인된 채널·DM 메시지에만 **업무 요청** 액션을 표시한다. 모달에서 원문을 참고하지만 공개 업무 제목은 빈 칸에서 직접 작성하게 해 DM 내용이 의도치 않게 팀 전체에 노출되지 않도록 했다. 담당자·미래 마감·예상 시간·검수 기간을 편집한 뒤 최종 저장할 때만 `createTask`를 호출한다.
- 발견한 문제/해결: 기존 채팅에는 Functions 객체가 전달되지 않아 워크스페이스에서 채팅까지 연결했다. 취소·Escape는 쓰기 없이 닫고, 저장 중 중복 제출을 막으며, 실패 시 입력값과 오류 안내를 유지한다. 로컬 기본 에뮬레이터가 실행 중이어서 브라우저 검증은 별도 포트에서 진행했다.
- 검증: Auth·Firestore·Functions 에뮬레이터와 두 Chrome 세션에서 채널 메시지의 취소·저장, DM 메시지의 공개 제목 직접 입력·검수 선택·저장을 확인했다. Firestore 업무 문서의 요청자·담당자·원본 ID·상태·검수 필드와 DM 원문 미포함을 확인했고, 기존 채팅·오프라인 복구 시나리오도 통과했다. `npm run typecheck`, `npm run lint`, 웹 빌드로 확인했다.
- 다음 일차에 넘길 사항: 19일차 AI 후보 제안. 저장된 업무의 편집·상태 전이와 업무 보드 표시 등은 이후 일차의 범위다.

## 포트폴리오 기록
- 문제 정의: 서버 업무 스키마가 있어도 채팅 메시지에서 수동으로 업무 요청을 만드는 화면이 없었다.
- 선택한 접근과 대안: 메시지별 명시적 액션과 편집 가능한 모달을 사용하고 확정 시에만 서버 저장을 요청했다. DM 문구를 자동 제목으로 채우면 공개 업무에 비공개 원문이 섞일 수 있어 빈 제목을 선택했다.
- 검증 근거(수치 임의 생성 금지): 브라우저 통합 테스트에서 취소 시 업무 0개, 채널 요청 후 1개, DM 요청 후 원문 필드 없는 업무가 저장됐다.
