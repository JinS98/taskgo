# 업무·검수 상태 정책

## 업무 요청
- REQUESTED → 담당자 수락 시 ACCEPTED → 담당자가 진행 시작 시 IN_PROGRESS.
- 담당자는 REQUESTED에서 거절할 수 있으며, REQUESTED·ACCEPTED·IN_PROGRESS에서 마감일 변경을 제안할 수 있다. 변경은 요청자가 승인해야 확정된다.
- 변경 승인 전 기존 확정 마감일과 업무 상태를 유지한다. 요청자가 변경을 거절하면 제안만 지운다.
- 요청 생성과 상태·마감 변경 이력은 업무 카드에서 확인한다.

## 검수
- 검수 미선택: 담당자 완료 → DONE.
- 검수 선택: 제출 → REVIEW_PENDING → 요청자 승인 DONE / 사유 포함 반려 REWORK.
- 22일차 구현: 담당자는 진행 중인 검수 대상 업무만 제출할 수 있다. 제출 시각과 검수 회차 1을 기록하고, 마감 변경 제안이 대기 중이면 제출을 막는다.
- REWORK 재제출 시 검수 회차 증가, 새 검수 기한 생성. 이전 예약 알림 무효화.
- 검수 기한까지 응답이 없으면 자동 DONE; `completionReason=REVIEW_TIMEOUT` 등으로 구분.

## 검수 기한

아래 근무시간·공휴일 계산과 검수 기한 저장은 24일차 작업 범위다. 22일차 제출에서는 `reviewDeadlineAt`을 아직 설정하지 않는다.
- Asia/Seoul 기준 월~금 09:00~12:00, 13:00~18:00, 공휴일·대체공휴일 제외.
- 1근무일 = 8근무시간.
- 예: 금 17시 제출 + 2근무일 → 화 17시(공휴일 없을 때).
- 예: 금 20시 제출 + 2근무일 → 화 18시(공휴일 없을 때).
- 제출 시 알림, 잔여 8/2근무시간 리마인드(중복 방지), 자동 완료 알림.
- 자동 완료와 승인/반려 동시 실행 시 트랜잭션으로 단일 결과 보장.
