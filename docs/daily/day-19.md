## 구현 메모
- 변경한 파일: `functions/src/taskSuggestions.ts`, `functions/src/index.ts`, `functions/scripts/prepare-emulator.mjs`, `functions/scripts/verify-task-model.mjs`, `functions/.env.example`, `functions/README.md`, `apps/web/src/features/tasks/`의 모달·API, README.
- 의사결정 및 이유: 사용자가 메시지에서 **업무 요청**을 연 뒤 **초안 제안받기**를 직접 누를 때만 제안 함수를 호출한다. 서버에서 워크스페이스 멤버십과 DM 참여 여부를 확인하고 선택한 메시지까지 같은 대화방의 최대 8개 메시지만 사용한다. 하루 사용자당 10회로 제한한다. 후보 선택은 공개 제목 입력만 채우며 저장은 별도 확인 버튼으로 한다.
- 발견한 문제/해결: 비공개 채널·DM 대화의 외부 전송이 명시적으로 승인되지 않아 자동 승인 검토가 처음에 거부했다. 사용자가 선택 버튼 클릭 시 OpenAI 전송을 승인한 후 실제 서버 호출 경로를 연결했다. 키가 없는 에뮬레이터는 외부 전송 없이 로컬 초안을 표시하고 AI 결과가 아님을 알린다.
- 검증: `npm run typecheck`, `npm run lint`, 웹·Functions 빌드, Auth·Firestore·Functions 에뮬레이터 권한/문맥 테스트와 OpenAI 요청·응답 모의 테스트 통과. 두 Chrome 세션의 채널·DM 초안 선택·제목 편집·확정 저장 테스트 통과. 실제 OpenAI 키가 없어 실제 모델 응답과 비용은 검증하지 못했다.
- 다음 일차에 넘길 사항: 비밀 `OPENAI_API_KEY` 설정 후 실제 OpenAI 제안·오류·비용 확인. 실서비스 Functions 배포는 별도.

## 포트폴리오 기록
- 문제 정의: 메시지에서 직접 업무를 작성하는 흐름은 있지만 제안 후보를 요청하거나 편집할 수 없었다.
- 선택한 접근과 대안: 권한을 서버에서 재확인하고 같은 방의 제한된 문맥만 읽는다. 승인 후 OpenAI Responses API에 `store: false`와 구조화된 후보 스키마를 적용했다. 키가 없는 로컬 환경만 문장 기반 초안을 사용한다.
- 검증 근거(수치 임의 생성 금지): 에뮬레이터에서 다른 워크스페이스·DM 접근 거부와 8개 문맥 제한을 확인했다. 모의 HTTP 응답으로 요청 형식·후보 검증·실패 처리를 확인했다. 두 Chrome 세션에서 명시적 버튼·후보 선택·제목 수정·저장 분리를 확인했다.
