## 구현 메모
- 변경한 파일: `apps/socket-server/src/app.ts`·`firebase.ts`·`scripts/verify-socket.mjs`, `shared/contracts/src/socket.ts`, `README.md`, `apps/socket-server/README.md`, `docs/02-architecture.md`·`03-data-model.md`·`04-socket-events.md`·`06-security-testing.md`, 이 문서.
- 의사결정 및 이유: 검증된 UID와 사용자별 `clientMessageId`에서 결정적 메시지 ID를 만든다. Firestore 트랜잭션에서 현재 멤버십·채널/DM 소속·기존 메시지를 읽고 최초 요청만 생성한다. 동일 요청의 재시도는 같은 ID로 성공 ACK를 돌려주며 다시 전파하지 않는다. 내용이나 룸이 다른 재사용은 `CONFLICT`로 거절한다.
- 발견한 문제/해결: 저장 실패 시 성공 ACK가 앞서 나가지 않도록 저장 완료 후 ACK를 보낸다. 멤버십·DM 참여자가 바뀐 소켓이 이전 룸에 남아 있을 수 있어 방송 직전 수신자별 권한을 확인하고 권한이 없으면 룸에서 제거한다. 첫 에뮬레이터 트랜잭션의 콜드 스타트가 기존 2.5초 테스트 ACK 제한을 넘겨 테스트 제한을 10초로 조정했다.
- 다음 일차에 넘길 사항: 13일차에 웹 채팅 UI를 실제 소켓과 Zustand에 연결하고 두 브라우저에서 송수신을 확인한다. 재연결 후 누락 메시지 조회와 타이핑 이벤트는 별도 후속 작업이다. 다중 서버 인스턴스에는 공유 소켓 어댑터와 수신자 권한 검사 설계가 필요하다.

## 포트폴리오 기록
- 문제 정의: ACK 손실과 동시 재시도에도 메시지를 한 번만 저장하면서 권한 없는 사용자에게 전파하지 않아야 했다.
- 선택한 접근과 대안: 서버 메모리의 중복 목록 대신 Firestore 트랜잭션과 결정적 문서 ID를 사용해 재시작 후에도 같은 결과를 얻도록 했다. ACK 전에 저장하고, 새로 생성된 메시지만 현재 권한이 있는 소켓에 전파한다.
- 검증 근거(수치 임의 생성 금지): `npm run test:socket`에서 채널·DM 문서 저장, 저장 후 ACK, 순차·동시 재전송, ID 충돌, 저장 실패 ACK, 다른 사용자와 같은 클라이언트 ID, Firestore 읽기·직접 쓰기 규칙, DM 참여자·워크스페이스 멤버십 제거 후 방송 차단을 확인했다. `npm run typecheck`가 통과했다.
