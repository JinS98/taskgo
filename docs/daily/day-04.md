## 구현 메모
- 변경한 파일: `apps/web/src/components/layout/WorkspaceLayout.tsx`, `WorkspaceLayout.module.scss`, `apps/web/src/App.tsx`, `App.module.scss`, `apps/web/src/features/chat/demoConversations.ts`, `apps/web/scripts/verify-sidebar.mjs`, 두 `package.json`, `package-lock.json`, `README.md`, 이 문서. 빈 `features/chat/.gitkeep` 제거.
- 의사결정 및 이유: 채널·DM 샘플 목록과 세 화면 버튼을 실제 선택 가능한 UI로 만들었다. 5일차 Zustand 도입 전까지는 React 로컬 상태를 사용하며, 채널·DM을 고르면 채팅 화면으로 돌아간다. 버튼에 선택 상태와 키보드 포커스를 표시한다.
- 예외 상황·권한·로딩 검토: 목록은 명시된 샘플 데이터이며 인증·네트워크 요청은 없다. 권한, 로딩, 서버 실패 상태는 실제 데이터 연동 일차에 처리한다. 좁은 화면에서도 채널·DM 목록을 가로로 탐색할 수 있게 했다.
- 발견한 문제/해결: 브라우저 연결 도구를 사용할 수 없어 직접 화면의 육안 확인은 남아 있다. React DOM 상호작용 검사에서 접근성 이름의 장식용 `#`이 제외되는 점을 확인해 검사를 실제 버튼 이름에 맞췄다.
- 다음 일차에 넘길 사항: 5일차 Zustand로 뷰·채널·DM 선택 상태를 옮긴다. 데스크톱·모바일 화면 육안 확인도 진행한다.

## 포트폴리오 기록
- 문제 정의: 정적 사이드 영역만 있어 사용자가 채널·DM이나 화면을 선택해 볼 수 없었다.
- 선택한 접근과 대안: 서버 연결 전임을 드러내는 샘플 목록으로 전환 흐름을 먼저 만들고 실제 메시지·업무 데이터는 표시하지 않았다.
- 검증 근거(수치 임의 생성 금지): `npm run typecheck`, `npm run lint`, `npm run build:web`, `npm run test:ui` 통과. UI 검사에서 보드·캘린더 전환, DM 선택 후 채팅 복귀, 채널 키보드 선택과 선택 표시를 확인했다. 브라우저 육안 검증은 미완료.
