## 구현 메모
- 변경한 파일: `apps/socket-server/src/app.ts`, `apps/web/src/features/chat/LiveChatPanel.tsx`, `ChatPanel.module.scss`, 소켓·브라우저 검증 스크립트, README와 소켓·보안 문서.
- 의사결정 및 이유: 타이핑은 저장하지 않는 일시적 이벤트로 다룬다. 서버는 발신자의 룸 참가와 현재 권한을 검증하고, 수신자에게 보내기 직전에도 권한을 확인한다. 웹은 작성 중 2.5초마다 상태를 갱신하고, 종료 이벤트를 놓쳐도 5초 후 표시를 지운다.
- 발견한 문제/해결: 15일차까지 `typing:set`이 `FEATURE_NOT_READY`로 거절됐다. 채널·DM에 범위를 제한해 전파하고 룸 퇴장·연결 해제 시 종료를 알리도록 했다. 연결 오류와 전송 오류가 같은 배너에 섞여 전송 실패에도 **다시 연결**이 나오던 문제를 분리했다. 모바일에서도 연결 상태 배지를 볼 수 있게 했다.
- 검증: `npm run test:socket`에서 입력 요청 형식, 권한 없는 룸 거절, 채널·DM 전파 범위, DM 참여 권한 철회 후 수신 차단을 확인했다. `npm run test:live-chat`에서 두 Chrome 세션의 입력 시작·종료, 오프라인 표시와 복구, 기존 대화 조회·전송 흐름을 확인했다. `npm run typecheck`, `npm run lint`, `npm run build:web`로 빌드 검증했다.
- 다음 일차에 넘길 사항: 17일차 업무 데이터 모델. 실제 배포 환경과 다중 소켓 서버 인스턴스 검증은 별도 진행이 필요하다.

## 포트폴리오 기록
- 문제 정의: 상대방이 글을 작성 중인지 알 수 없고, 연결·전송 오류가 같은 안내로 표시됐다.
- 선택한 접근과 대안: 권한을 확인하는 일시적 소켓 이벤트와 자동 만료 표시를 사용했다. 타이핑을 Firestore에 저장하면 불필요한 쓰기와 오래된 상태가 남는다.
- 검증 근거(수치 임의 생성 금지): 소켓 에뮬레이터 권한 테스트와 두 Chrome 세션의 채널·DM 입력 표시 및 오프라인 복구 테스트가 통과했다.
