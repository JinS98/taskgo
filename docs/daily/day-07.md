## 구현 메모
- 변경한 파일: `apps/web/src/features/auth/`의 인증 화면·세션 훅·계정 메뉴·오류 메시지, `src/main.tsx`, `src/App.tsx`, `src/components/layout/WorkspaceLayout.*`, `src/store/useWorkspaceNavigationStore.ts`, `scripts/verify-auth.mjs`, 두 `package.json`, `package-lock.json`, `README.md`, 이 문서.
- 의사결정 및 이유: `/login`, `/verify-email`, `/workspace`로 화면을 나누고 Firebase 인증 상태 관찰자로 접근을 제어한다. 이메일 가입자는 확인 링크를 처리하고 앱에서 인증 상태를 새로고침해야 워크스페이스에 들어간다. Google 인증 계정은 확인된 이메일을 사용한다. 계정 메뉴에서 Google 연결 또는 비밀번호 추가를 제공해 로그인 방식 변경 후에도 동일 Firebase UID를 유지한다. 충돌 계정은 데이터 손실을 막기 위해 자동 병합하지 않는다.
- 예외 상황·권한·로딩 검토: 초기 인증 상태 및 요청 중 로딩 UI, 설정 누락·네트워크·잘못된 자격증명·중복 이메일·팝업 취소·계정 충돌·재로그인 필요 오류를 안내한다. 로그아웃 시 샘플 워크스페이스 선택 상태를 초기화한다. Firestore는 8일차까지 차단 규칙을 유지한다.
- 발견한 문제/해결: Google 계정에 비밀번호를 추가할 때 `linkWithCredential` 호출이 로컬 검증에서 끝나지 않아 `updatePassword`를 사용했다. 에뮬레이터에서 비밀번호 로그인 후 UID가 유지되는 것을 확인했다. 헤드리스 Chrome에서는 Google 팝업이 열렸지만 에뮬레이터의 프레임 전달 오류로 선택을 완료하지 못했다.
- 다음 일차에 넘길 사항: 실제 브라우저에서 Google 팝업 계정 선택을 수동 확인한다. 8일차에는 멤버십 기반 Firestore 규칙과 데이터 모델을 구현한다.

## 포트폴리오 기록
- 문제 정의: Firebase 공급자 설정만으로는 사용자가 가입·로그인할 수 없고, 미확인 이메일이나 비로그인 사용자가 샘플 워크스페이스에 들어갈 수 있었다.
- 선택한 접근과 대안: Firebase 인증 상태를 화면의 단일 기준으로 삼고, 가입 직후 이메일 확인을 요구했다. 로그인 방식 연결은 UID 유지 여부를 검증했고 충돌 시 자동 병합 대신 명시적 오류를 선택했다.
- 검증 근거(수치 임의 생성 금지): `npm run test:auth`에서 비로그인 보호 경로, 이메일 가입·확인·로그아웃·재로그인, Google 에뮬레이터 자격증명 로그인과 비밀번호 추가 후 동일 UID 재로그인을 확인했다. 브라우저에서는 로그인 화면과 Google 인증 팝업 열림을 확인했다. `npm run typecheck`, `npm run lint`, `npm run build:web`, `npm run test:ui`를 통과했다. Google 팝업 계정 선택 및 실제 프로젝트 로그인은 아직 수동 검증이 필요하다.
