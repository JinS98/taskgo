## 구현 메모
- 변경한 파일: `shared/contracts/src/task.ts`, `functions/src/taskModel.ts`, `functions/src/taskResponses.ts`, `apps/web/src/features/tasks/TaskBoardPanel.*`, `TaskCalendarPanel.tsx`, 검증 스크립트와 관련 문서.
- 의사결정 및 이유: 검수 기간은 업무 요청 시 1~10근무일로 선택한다. 담당자가 `IN_PROGRESS` 업무를 제출하면 `REVIEW_PENDING`으로 옮기고 제출 시각·첫 검수 회차를 업무와 이력에 함께 기록한다. 검수 기한의 공휴일 포함 계산은 24일차에 구현한다.
- 발견한 문제/해결: 검수 대상이 아닌 업무와 마감 변경 제안 대기 업무의 제출을 서버에서 거부한다. 중복 제출은 트랜잭션에서 한 번만 성공하도록 검증했다.
- 검증: 타입 검사·린트·웹/Functions 빌드, Auth·Firestore·Functions 에뮬레이터의 권한·상태·중복 제출 테스트와 두 Chrome 계정에서 제출→요청자 검수 대기 표시→이력 조회를 통과했다.
- 다음 일차에 넘길 사항: 23일차 승인·반려·재제출, 24일차 검수 기한의 근무시간·공휴일 계산.

## 포트폴리오 기록
- 문제 정의: 검수 기간을 선택해 업무를 만들 수 있었지만 담당자가 검수를 요청하는 단계가 없었다.
- 선택한 접근과 대안: 클라이언트의 직접 쓰기 대신 기존 서버 함수의 역할·상태 검증과 이벤트 트랜잭션을 확장했다.
- 검증 근거(수치 임의 생성 금지): 중복 제출 2건 중 1건만 성공했고, 두 계정 브라우저에서 `REVIEW_PENDING`과 제출 이력을 확인했다.
