## 구현 메모
- 변경한 파일: `apps/web/src/features/chat/ChatPanel.tsx`, `ChatPanel.module.scss`, `useDemoChatStore.ts`, `apps/web/src/App.tsx`, `apps/web/src/components/layout/WorkspaceLayout.*`, `apps/web/src/features/auth/authActions.ts`, `apps/web/src/features/workspace/WorkspaceGate.tsx`, `apps/web/scripts/verify-chat.mjs`, 두 `package.json`, `README.md`, 이 문서.
- 의사결정 및 이유: 10~12일차 소켓 서버·인증·영속화 전에 채팅 본문을 독립된 UI로 구현했다. 채널/DM 샘플 메시지를 표시하고 입력은 사용자·워크스페이스·대화별 메모리 상태로 관리한다. 전송 상태는 로컬 미리보기 진행·완료·실패로 표시해 실제 서버 전송으로 오해하지 않게 했다. 채팅 본문은 전체 높이를 쓰고 메시지 목록 내부만 스크롤한다.
- 예외 상황·권한·로딩 검토: 빈 메시지 전송을 막고 2,000자로 제한한다. Enter 전송, Shift+Enter 줄바꿈, 실패 시 재시도 UI를 제공한다. 로그아웃 시 초안·미리보기 메시지를 삭제하고 사용자 ID와 워크스페이스 ID를 상태 키에 포함한다. DM과 채널의 샘플 메시지는 실제 사용자 데이터가 아니다.
- 발견한 문제/해결: 테스트의 줄바꿈 텍스트 정규화와 React 외부 상태 초기화 경고를 고쳐 검증했다.
- 다음 일차에 넘길 사항: 10~12일차에 Socket.io 연결·인증·Firestore 저장·ACK를 구현하고 로컬 미리보기 전송 함수를 실제 전송으로 교체한다. 실제 채널/DM 목록과 과거 메시지 조회는 후속 일차에 연결한다.

## 포트폴리오 기록
- 문제 정의: 기존 채팅 뷰는 소개 카드만 보여 실제 대화 목록이나 입력·전송 상태를 확인할 수 없었다.
- 선택한 접근과 대안: 전송 인터페이스와 표시 상태를 분리해 지금은 로컬 미리보기로 동작하고, 이후 서버 ACK에 연결할 수 있게 했다.
- 검증 근거(수치 임의 생성 금지): `npm run test:chat`에서 메시지 입력·전송 중/완료·실패 재시도·줄바꿈·대화/워크스페이스/사용자 분리를 확인했다. `npm run test:ui`, `npm run test:auth`에서 화면 전환과 로그아웃 시 초안 삭제를 확인했고 타입 검사, 린트, 웹 빌드를 통과했다.
