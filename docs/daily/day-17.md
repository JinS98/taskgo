## 구현 메모
- 변경한 파일: `shared/contracts/src/task.ts`, `functions/src/taskModel.ts`, `functions/src/index.ts`, `functions/scripts/verify-task-model.mjs`, 패키지 스크립트, README와 데이터 모델·보안 문서.
- 의사결정 및 이유: 업무 생성은 서버 호출 함수에서만 허용하고 Firestore 클라이언트 직접 쓰기를 계속 차단한다. 요청자 UID와 원본 유형은 서버가 확인된 사용자·저장된 메시지에서 정한다. 마감은 UTC ISO 요청값을 Firestore Timestamp로 저장한다. DM 원문·룸 ID는 팀 공개 업무 문서에 복사하지 않는다.
- 스키마: `REQUESTED` 상태로 생성하며 담당자·미래 마감·검수 선택/근무일(1~10)·예상 시간(선택 시 15~480분)을 기록한다. 제안 마감·검수 기한·완료 사유는 null, 검수 회차는 0이다. 원본 메시지와 워크스페이스·채널/DM 소속을 트랜잭션에서 확인한다.
- 발견한 문제/해결: 기존에는 `tasks` 읽기 규칙과 필드 초안만 있고 생성 경로가 없었다. 원본 DM의 비참여자도 업무는 읽을 수 있어야 하므로 원문 접근 권한은 메시지 규칙에 맡기고 공개 업무에는 메타데이터만 담았다. 기본 에뮬레이터 포트가 실행 중이어서 검증은 별도 포트에서 진행했다.
- 검증: `npm run typecheck`, `npm run build:functions` 통과. Auth·Firestore·Functions 에뮬레이터에서 요청자·상태 위조, 비회원 담당자, 잘못된 마감·검수 값, 타 워크스페이스/비참여 DM 원본을 거절했다. 정상 채널·DM 업무 문서의 필드와 멤버 읽기, 원본 DM 비참여자 읽기 거절, 클라이언트 직접 업무 쓰기 거절을 확인했다.
- 다음 일차에 넘길 사항: 18일차에 메시지의 업무 생성 UI와 편집·확정 흐름을 `createTask`에 연결한다. 업무 상태 전이와 검수 기한 계산은 후속 일차에서 구현한다.

## 포트폴리오 기록
- 문제 정의: 팀에 공개할 업무 메타데이터와 비공개 DM 원문을 분리하면서 요청자·담당자·마감·검수 값을 신뢰할 수 있어야 한다.
- 선택한 접근과 대안: 서버 트랜잭션에서 현재 멤버십과 원본 대화 접근권을 확인하고 초기 필드를 확정한다. 클라이언트의 직접 Firestore 쓰기는 권한 위조를 막기 어려워 허용하지 않았다.
- 검증 근거(수치 임의 생성 금지): 로컬 에뮬레이터 통합 테스트에서 정상 채널·DM 생성과 위조·권한 실패 케이스가 통과했다. 업무 문서에 원문 필드가 없고, DM 비참여자는 업무만 읽을 수 있었다.
