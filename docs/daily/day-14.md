## 구현 메모
- 변경한 파일: `apps/web/src/features/chat/messageHistory.ts`·`useRoomHistory.ts`·`useLiveChatStore.ts`·`LiveChatPanel.tsx`·`ChatPanel.module.scss`, `firestore.indexes.json`, 브라우저 통합 테스트, README·아키텍처·이벤트·데이터 모델 문서.
- 의사결정 및 이유: 쿼리를 워크스페이스·룸 종류·룸 ID로 제한하고 생성 시각과 문서 ID를 내림차순 정렬해 한 번에 30개를 읽는다. 마지막 문서 스냅샷으로 다음 페이지를 조회한다. 과거 내역·소켓 이벤트·전송 ACK는 메시지 ID와 클라이언트 ID로 합친다.
- 발견한 문제/해결: 새 메시지만 메모리에 남아 새로고침이나 룸 재입장 후 이전 대화가 비었다. 첫 페이지를 자동으로 읽고 이전 페이지 버튼으로 더 읽는다. 위쪽에 메시지를 추가할 때 스크롤 높이 차이를 보정해 보던 위치를 유지한다. 재연결 후에는 기존 최신 메시지에 닿을 때까지 페이지를 조회해 누락분을 복원한다.
- 다음 일차에 넘길 사항: 15일차에 입력 중 표시와 읽음 상태를 검토한다. 실제 Firebase 프로젝트의 메시지 복합 인덱스와 소켓 서버 배포는 별도 작업이며, 로컬 에뮬레이터 검증이 실제 배포를 뜻하지는 않는다.

## 포트폴리오 기록
- 문제 정의: 실시간 대화는 가능했지만 새로고침·룸 전환 시 저장된 메시지를 확인할 수 없었다.
- 선택한 접근과 대안: 전체 메시지 구독 대신 권한이 걸린 룸별 Firestore 페이지 쿼리를 사용한다. 과거 페이지를 가져와도 현재 메시지와 중복 없이 병합하고 스크롤 위치를 보존한다.
- 검증 근거(수치 임의 생성 금지): `npm run test:live-chat`에서 두 Chrome 세션으로 채널의 65개 과거 메시지, 두 번의 이전 페이지 로딩, 스크롤 위치 유지, DM 과거 내역, 새로고침 후 대화 복원을 확인했다. `npm run typecheck`와 `npm run lint`가 통과했다.
