## 구현 메모
- 변경한 파일: `functions/src/taskResponses.ts`, `shared/contracts/src/task.ts`, `apps/web/src/features/tasks/TaskBoardPanel.*`, 두 에뮬레이터 검증 스크립트, README·상태 정책·데이터 모델 문서.
- 의사결정 및 이유: 담당자의 `startProgress`만 `ACCEPTED → IN_PROGRESS`로 전이한다. 마감 제안·요청자 승인·거절은 `REQUESTED`뿐 아니라 `ACCEPTED`·`IN_PROGRESS`에서도 허용한다. 제안 중에도 확정 마감과 업무 상태를 유지하며, 진행 시작은 마감 응답을 기다리는 동안에도 가능하다.
- 이력: 상태 변경과 마감 협의는 업무 문서와 `taskEvents`에 한 트랜잭션으로 기록한다. 보드는 카드를 열 때 해당 업무 이력만 실시간 구독한다. 예전 업무에는 생성 이벤트가 없으므로 `createdAt`을 요청 생성 항목으로 표시한다.
- 발견한 문제/해결: 기존 함수가 모든 응답을 `REQUESTED`로 제한하고 보드에 이력 화면이 없었다. 액션별 상태 조건과 담당자·요청자 권한을 분리하고 이력 읽기 권한을 에뮬레이터로 확인했다. 기본 에뮬레이터 포트가 사용 중이어서 테스트에는 별도 포트를 사용했다.
- 검증: 타입 검사·린트·웹/Functions 빌드, Auth·Firestore·Functions 에뮬레이터에서 중복 진행 시작 2건 중 1건만 성공, 진행 중 마감 제안·승인/거절·상태 보존·비멤버 이력 조회 차단을 확인했다. 두 Chrome 계정에서 진행 시작→마감 재제안→요청자 승인→업무 이력 표시를 확인했다.
- 다음 일차에 넘길 사항: 22일차 검수 제출과 `REVIEW_PENDING` 전이. 현재 이력은 업무 요청·진행·마감 협의까지만 표시한다.

## 포트폴리오 기록
- 문제 정의: 담당자가 요청을 수락한 뒤 업무를 진행 중으로 바꿀 수 없고, 진행 중에는 마감 협의도 막혔다.
- 선택한 접근과 대안: 상태별 버튼만 숨기는 방식 대신 서버 트랜잭션에서 역할·상태·기존 제안을 검증하고 기록을 함께 저장한다.
- 검증 근거(수치 임의 생성 금지): 중복 진행 시작 2건 중 1건만 성공했다. 브라우저 두 계정에서 마감 승인 전 기존 날짜 유지, 승인 후 `IN_PROGRESS` 유지와 이력 표시를 확인했다.
