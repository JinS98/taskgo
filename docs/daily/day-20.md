## 구현 메모
- 변경한 파일: `functions/src/taskResponses.ts`, `functions/src/index.ts`, `shared/contracts/src/task.ts`, `apps/web/src/features/tasks/TaskBoardPanel.*`, `taskResponseApi.ts`, `apps/web/src/App.tsx`, 에뮬레이터·브라우저 테스트 및 관련 문서.
- 의사결정 및 이유: `respondTask` 호출형 함수에서 요청 상태와 담당자·요청자 권한을 트랜잭션으로 확인한다. 담당자만 수락·거절·마감 변경을 제안하고 요청자만 제안을 승인·거절한다. 제안 중에는 기존 마감일이 유지되고 승인 뒤에도 상태는 `REQUESTED`로 남아 담당자가 별도로 수락한다. 모든 응답을 `taskEvents`에 기록한다.
- 발견한 문제/해결: 기존 업무 보드는 미리보기여서 요청 응답 동작을 할 수 없었다. 실제 업무를 구독하는 보드와 상태별 필터·권한별 액션·오류 안내를 연결했다. 동시 수락은 서버 트랜잭션에서 한 번만 성공하도록 확인했다.
- 검증: Auth·Firestore·Functions 에뮬레이터에서 담당자·요청자·비멤버 권한, 잘못된 날짜·필드, 제안 중 기존 마감 유지, 승인·거절, 동시 수락, 거절 및 이벤트 수를 확인했다. 두 Chrome 세션에서 마감 제안→요청자 승인→담당자 수락과 별도 DM 업무 거절을 확인했다. 타입 검사와 웹 빌드·린트 결과를 함께 확인했다.
- 다음 일차에 넘길 사항: 21일차 진행 시작과 진행 중 마감 협의. 이후 사용자가 승인한 [UI/UX 시안](../design/README.md)의 밝은 테마와 화면 구조를 앱에 반영했다.

## 포트폴리오 기록
- 문제 정의: 업무 요청을 만들 수는 있었지만 담당자가 수락·거절하거나 마감을 협의할 수 없었다.
- 선택한 접근과 대안: Firestore 클라이언트 쓰기를 열지 않고 서버 함수가 역할·상태를 검증한다. 제안 날짜는 별도 필드에 보관해 요청자 승인 전 확정 마감을 보존한다.
- 검증 근거(수치 임의 생성 금지): 에뮬레이터 전이 테스트에서 동시 수락 2건 중 1건만 성공했다. 브라우저에서 두 계정의 제안·승인·수락·거절 흐름을 확인했다.
