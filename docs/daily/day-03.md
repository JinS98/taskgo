## 구현 메모
- 변경한 파일: `apps/web/src/components/layout/WorkspaceLayout.tsx`, `WorkspaceLayout.module.scss`, `apps/web/src/App.tsx`, `App.module.scss`, `apps/web/src/styles/global.scss`, `README.md`, 이 문서. 빈 `components/layout/.gitkeep` 제거.
- 의사결정 및 이유: 고정 사이드 영역과 본문을 CSS Grid의 2열로 구성하고, 760px 이하에서는 상단 브랜드 영역과 본문을 세로로 배치했다. 브랜드 색상은 `docs/09-branding.md`를 따랐다.
- 범위: 사이드 영역은 워크스페이스·채널 자리만 보여준다. 채널·DM 목록 및 전환은 4일차, 상태 관리는 5일차에 구현한다. 준비 중인 기능은 화면에 명시해 실제 동작으로 오해하지 않게 했다.
- 예외 상황·권한·로딩 검토: 현재 화면은 정적 미리보기라 인증·네트워크 요청이 없다. 접근 권한이나 비동기 로딩·실패 상태는 해당 기능 구현 일차에서 처리한다. 작은 화면에서는 빈 탐색 영역을 숨겨 본문 폭을 확보한다.
- 발견한 문제/해결: 브라우저 자동화가 현재 URL을 안전하게 판별하지 못해 시각 확인이 중단되었다. 로컬 렌더링과 HTTP 응답은 검증했으며 실제 화면 육안 확인은 남아 있다.
- 다음 일차에 넘길 사항: 4일차 채널·DM 사이드바와 뷰 전환 UI. 먼저 데스크톱·모바일 화면을 육안 확인한다.

## 포트폴리오 기록
- 문제 정의: 초기 화면은 워크스페이스의 사이드 영역과 본문 영역을 구분하지 못했다.
- 선택한 접근과 대안: 현재 소개 내용을 새 레이아웃 안에 배치하고, 실제 기능처럼 보이는 가짜 메뉴나 버튼은 만들지 않았다.
- 검증 근거(수치 임의 생성 금지): `npm run typecheck`, `npm run lint`, `npm run build:web` 통과. React 로컬 렌더링에서 `<aside>`, `<main>`, 소개와 세 영역 카드 확인. Vite 개발 서버의 `/`, `/src/App.tsx`, 레이아웃 SCSS 모듈 모두 HTTP 200 확인. 시각 검증은 미완료.
