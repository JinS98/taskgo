## 구현 메모
- 변경한 파일: `apps/web/src/features/chat/`의 실제 채팅 패널·Zustand 상태·룸 목록 구독, `App.tsx`·`WorkspaceLayout.tsx`·`WorkspaceGate.tsx`, 소켓 서버의 기본 채널 생성, Firestore DM 복합 인덱스, 브라우저 통합 테스트, 실행 환경·README·아키텍처·이벤트 문서.
- 의사결정 및 이유: 로그인한 워크스페이스에서는 실제 Firestore 채널·DM만 보여주고 독립 미리보기에서만 샘플 대화를 유지한다. 기본 `전체` 채널은 서버가 입장 권한을 확인한 뒤 생성한다. 전송 ACK와 브로드캐스트가 서로 다른 순서로 도착해도 클라이언트 ID로 한 메시지로 합친다.
- 발견한 문제/해결: 기존 샘플 채널 ID는 실제 Firestore 문서와 연결되지 않았다. 워크스페이스별 기본 채널과 실시간 목록을 연결했다. DM은 워크스페이스와 참여자 조건으로만 조회하고 필요한 복합 인덱스를 추가했다. 룸별 초안·메시지는 로그아웃 시 초기화한다.
- 다음 일차에 넘길 사항: 14일차에 과거 메시지 조회·페이지네이션과 재연결 후 누락 복구를 구현한다. DM 생성 UI와 서버 측 생성 정책은 별도 후속 작업이다. 실제 Firebase/Cloud Run 배포는 아직 수행하지 않았다.

## 포트폴리오 기록
- 문제 정의: 12일차 서버 저장·전파 기능이 웹 채팅 화면과 분리되어 사용자는 실시간 대화를 직접 확인할 수 없었다.
- 선택한 접근과 대안: Firebase 인증 사용자만 소켓에 접속하고 룸 참가 ACK 이후 전송한다. 로컬 메시지를 즉시 표시한 뒤 서버 ACK/이벤트로 확정하며, 실패 시 같은 클라이언트 ID로 재시도한다.
- 검증 근거(수치 임의 생성 금지): `npm run test:live-chat`에서 Chrome 두 세션으로 기본 채널 생성, 양방향 채널 송수신, DM 송수신, 룸 전환 후 화면 분리와 중복 없는 표시를 확인했다. `npm run typecheck`, `npm run lint`, `npm run build:web`, `npm run test:chat`, `npm run test:ui`가 통과했다. 소켓 회귀 테스트 `npm run test:socket`도 실행했다.
